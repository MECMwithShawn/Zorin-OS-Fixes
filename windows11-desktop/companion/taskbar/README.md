# Native taskbar previews

This extension builds [Xfce Docklike 0.5.0](https://github.com/xfce-mirror/xfce4-docklike-plugin/tree/9dc36e03d1b4d685b8eb76c02e701ccfbcc55bc8) with the adjacent patch and `LivePreview` / `SnapGroups` source files. The upstream source archive is pinned by commit and SHA-256 in `../taskbar_build.py`. Upstream copyright notices remain intact; Docklike and these C++ changes are GPL-3.0-or-later. See `COPYING`.

The existing Docklike launcher/grouping implementation remains responsible for pins, running indicators, app matching and window activation/closure. The patch changes the hover delay, preview layout and capture loop, and gives launcher-less apps stable grouping metadata instead of a new identity for every window. A GTK popup contains bounded horizontal cards with native close buttons. Wide groups scroll within the monitor. Hovering does not take keyboard focus; clicking a card activates/restores its window and dismisses the popup. Close uses Xfce's normal window close request, preserving application confirmation dialogs.

`LivePreview` invokes the companion's disposable `window_preview.py` reader asynchronously. At most two helpers run across all cards, with a two-second deadline and one request per card. Refresh timers are staggered around 200 ms, run while the flyout is visible, and stop on dismissal. Helpers never receive a shell command. Weak widget references and destruction handlers isolate close/capture races. Cached thumbnails stay in widget memory; minimized or uncapturable windows retain their last image or use their app icon. No production screenshots are saved or sent anywhere. Availability and frame rate depend on the compositor and application.

`SnapGroups` adds combined layout cards to the member apps' flyouts. The companion exports a typed, session-only `local.zorin11.SnapGroups` D-Bus interface: `List` returns opaque tokens and XID/rectangle values; `Activate` accepts a known token and preferred member XID. Geometry and membership remain authoritative in the companion, which rechecks live clients and desktop membership before restoring. Closed clients are removed immediately; fewer than two removes a group. Tokens are random and never persisted. Owner loss clears the panel cards, and old tokens cannot launch apps or restore windows after a restart. Task View uses the same activation path.

The native client uses asynchronous calls with deadlines and weak widget references. It refreshes membership only in visible flyouts and resolves native window objects synchronously. Layout tiles share the existing two-worker capture limit, rotate priority between members, and use cached images/icons when minimized. A closed member updates an open flyout; an individual Close button never closes an entire group.

`taskbar_build.py` builds into `~/.cache/zorin11-taskbar`, runs Meson's staged install to remove build RPATHs, and records an artifact hash. The companion installer copies the library and descriptor into the user's Xfce plugin directories. It never replaces `/usr` libraries. Both files and the scoped CSS are recorded in the existing compare-safe recovery manifest; restore returns to the distribution plugin. Source/build tools are needed only when the cached module must be rebuilt. The laptop dependency script includes them.

Validation: run `python3 test_taskbar_live.py` from the companion directory, sequentially with other Xephyr tests. It uses a private display, D-Bus session, configuration, plugin installation and disposable windows under Xfwm and Compiz. Optional `ZORIN11_TEST_SCREENSHOTS=/absolute/path` saves test-only visual references.
